# MotionLab 设计文档

> 一个个人探索型 motion 工作台：用大白话描述，LLM 写 Remotion 动画代码，本地渲染成几十秒的 mp4。

- **状态**：设计待审
- **日期**：2026-09-30
- **归属**：`agents/motionlab/`（先独立跑通，之后并入多媒体工作台集合）

---

## 1. 背景与意图

转转已有 `posterdesigner`（生图工具台，`gpt-image-2` 出海报）。现在想把"多媒体产出"做成一个集合，第一步先单独做透**视频/motion** 这一块。

**关键约束（已确认的现实）**：手上网关（`apiproxy.paigod.work`）目前只有两个**语言模型**——`gpt-6-astra` 与 `claude-opus-5-5`，均只支持文字对话端点（Chat / Responses / Messages），**没有任何视频生成模型**。因此不走"AI 出画面"，改走**方向二：LLM 生成动画代码 → 本地渲染成视频**。

### 用途与成功标准

- **用途**：个人**探索型工具台**，核心是"试一下 motion"——快速出片段、看效果、找感觉，产出先不对外。
- **设计取向**：轻、迭代快、调参方便；不背团队协作 / 权限 / 交付规范的包袱。
- **成功标准**：
  1. 用大白话描述，能稳定拿到一段能播放的 motion（失败大部分被自愈机制吸收，用户少感知）。
  2. 生成后能在界面上实时微调参数（不重新调 LLM）。
  3. 满意后一键渲染成几十秒的 mp4。
  4. 每次生成有 token 成本估算，累计可见。

### 明确不做（YAGNI）

- 不做 AI 实拍/写实画面生成（网关无此能力）。
- 不做团队协作、多用户、权限、云端部署（个人本地工具）。
- 不做与 posterdesigner 的合并（本期只独立跑通，合并是后续独立任务）。
- 不做"导演+码农"双模型分工（本期只做模型切换）。

---

## 2. 范围内容

**motion 类型：通用台（D）**——信息/品牌动效、UI/交互动效、生成式图形三类都要能覆盖。这是选 Remotion 的直接原因：CSS 动画、GSAP、SVG、canvas 粒子、shader 都能塞进 React 组件统一渲染。

**交互模式：A + B**——先跑通"描述 → 出片"主链路（A），再叠加参数面板实时微调（B）。

**模型策略：切换（A）**——界面上 `Opus 5.5 ⇄ GPT-6-astra` 随时切，对比着玩。

## 3. 架构

三层，各管各事，通过明确接口通信：

```
┌─────────────────────────────────────────────┐
│  ① 工作台界面 (web/index.html)                │
│    · 对话框：大白话描述想要的 motion          │
│    · 模型切换：Opus 5.5 ⇄ GPT-6-astra        │
│    · 实时预览：@remotion/player               │
│    · 参数面板：照 propsSchema 自动长出         │
│    · 成本条：本次 token 估算 + 累计            │
├─────────────────────────────────────────────┤
│  ② 编排层 (本地 node 服务)                    │
│    · 收描述 → 拼 prompt → 调 LLM              │
│    · 拿回组件代码 → 契约校验 → 自愈重试        │
│    · 落盘 → 触发渲染 → mp4 到 output/         │
│    · 算 token 成本                            │
├─────────────────────────────────────────────┤
│  ③ 渲染引擎 (Remotion，本地)                  │
│    · 组件 + props → mp4（headless Chromium）  │
│    · 几十秒时长、精确可控                     │
└─────────────────────────────────────────────┘
```

**目录结构**（沿用 posterdesigner 习惯）：

```
agents/motionlab/
├── README.md
├── config.json           # 模型端点、官方原价、折扣系数、渲染默认参数
├── package.json
├── web/
│   └── index.html        # 单页工作台
├── server/               # ② 编排层
│   ├── index.js          # 本地 http 服务
│   ├── llm.js            # 调 LLM（Opus / GPT-6 两套端点）
│   ├── contract.js       # 契约校验三道闸 + 自愈循环
│   ├── render.js         # 调 Remotion 渲染
│   └── cost.js           # token 成本估算 + 累计持久化
├── remotion/             # ③ 渲染引擎
│   ├── Root.tsx          # Remotion 注册入口
│   └── generated/        # LLM 生成的组件落盘于此
├── output/               # 渲染出的 mp4
├── .cost.json            # 累计成本（本地持久化）
└── motionlab.command     # 一键启动
```

### 数据流（一次完整生成）

```
你描述
  → ② 拼 prompt 调 LLM（你选的模型）
  → 拿回带 propsSchema 的 Remotion 组件代码
  → ② 契约校验（3 道闸）→ 不过则自愈重试（≤2 次）
  → 落盘到 remotion/generated/
  → ① @remotion/player 实时预览
  → 你拖参数面板微调（仅改 props，不调 LLM）
  → 满意 → ② 触发 Remotion 渲染
  → mp4 存 output/（文件名带时间戳）
```

## 4. 各层详细设计

### ② 编排层：契约 + 校验 + 自愈（核心）

LLM 写代码天然会飘，用三个机制拦住：

**1. 固定契约**——每次生成必须满足：

- `export` 一个 React 组件 + 一个 `propsSchema`（用 zod 定义）。
- 所有可调项（颜色/时长/文案/速度…）必须走 props，**不许写死**。
- 用 Remotion 帧驱动范式：`useCurrentFrame()` / `interpolate()`。
- 时长、fps、尺寸由外部传入，组件不自己定。

`propsSchema` 是关键：**参数面板照它自动生成**。LLM 声明 `titleColor: color`、`speed: number(0.5~2)`，面板就自动出取色器 + 滑块。A 与 B 靠它接上。

**2. 三道校验闸**（收到代码后、渲染前）：

- 闸①**静态检查**：能否 parse？有无 export 组件与 schema？
- 闸②**schema 校验**：propsSchema 合法？props 都有默认值？
- 闸③**试渲染 1 帧**：真能渲染？抓取报错信息。

**3. 自愈循环**：任一闸不过，不直接报错给用户，而是把错误信息回喂 LLM 让它修，**最多自动重试 2 次**。2 次仍失败才提示用户换说法。

### ① 界面（web/index.html）

沿用 posterdesigner 单页风格，纯静态 + 调本地 ② 服务。布局：

```
┌──────────────────────────────────────────┐
│ [模型: Opus 5.5 ▾]      成本: ¥0.12/累计¥3.4 │
├─────────────────────┬────────────────────┤
│  预览区              │  参数面板           │
│  @remotion/player    │ (照 propsSchema     │
│  ▶ 实时播放          │  自动生成)          │
│                      │  · 标题文案 [____]  │
│                      │  · 主色    [🎨]     │
│                      │  · 速度    [——●—]   │
├─────────────────────┴────────────────────┤
│  对话框: 描述你想要的 motion... [生成]      │
│  [渲染成 mp4]                              │
└──────────────────────────────────────────┘
```

- 改参数面板 → player 实时变（不调 LLM）。
- 改描述点生成 → 走 LLM 出新版。

### ③ 渲染 + 成本估算

- **渲染**：`@remotion/renderer` 本地 headless Chromium，组件 + 当前 props → mp4 存 `output/`，文件名带时间戳（与 posterdesigner 一致，如 `20260930-153000-motion.mp4`）。
- **成本**：仅 LLM token（渲染本地免费）。计费公式：

  > 实际花费 = 官方原价/token × 折扣系数 × token 数

  折扣系数已知（`gpt-6-astra` 0.68 / `claude-opus-5-5` 0.46，为官方原价的折扣）；**官方原价（每百万 token 输入/输出费率）待实现阶段填入 `config.json`**（由转转提供或查网关/官方文档确认）。② 每次调完 LLM 拿 usage，按上式估算，界面成本条实时显示"本次 + 累计"（区分输入/输出 token）。累计存 `.cost.json`，跨会话保留。

## 5. 错误处理

| 场景 | 处理 |
|------|------|
| LLM 生成的代码过不了校验 | 自愈重试 ≤2 次；仍失败则提示用户换描述 |
| LLM 调用失败（网络/超时） | 界面明确报错，可重试；不静默吞掉 |
| 渲染超时/崩溃 | 抓 Remotion 报错回显；保留失败组件便于排查 |
| 参数面板输入越界 | 按 propsSchema 的 min/max 约束，前端拦截 |

---

## 6. 测试策略

- **契约校验层**：单测三道闸——喂合规代码、缺 export、坏 schema、渲染报错各一组，验证判定正确。
- **自愈循环**：mock LLM 返回坏代码，验证重试与最终放弃逻辑。
- **成本估算**：给定 usage 与系数，验证金额与累计持久化正确。
- **端到端**（手动）：跑一个真实描述，确认能出可播放 mp4；覆盖 A/B/C 三类各试一个典型 motion。

---

## 7. 技术选型确认

| 项 | 选择 | 理由 |
|----|------|------|
| 渲染框架 | **Remotion** | React 视频框架，能统一承载 CSS/GSAP/SVG/canvas/shader，精确控时长，渲染 mp4 |
| 预览 | `@remotion/player` | 改 props 实时预览，不重渲染 |
| 参数校验 | zod | 定义 propsSchema，前端面板照它生成 |
| 服务 | 本地 node http | 与 posterdesigner 一致的本地工作台模式 |
| 语言模型 | Opus 5.5 / GPT-6-astra（切换） | 网关现有；写代码强项 |
