# 星群叙事模块 / Starline Module

## 1. 模块定位 / Purpose

这是一份独立于功能说明、运行规则和协作流程之外的世界观文本。

它的目标不是解释系统怎么工作，而是解释这个团队为什么像这样存在。

这里的内容采用两种口吻并行书写：

- `故事书`：偏文学、散文、科幻叙事，用来建立氛围、想象与情绪
- `说明书`：偏结构化、逻辑化、可引用，用来解释名词、关系与状态

这两个部分共同构成同一条 `Story Line`。  
它们不负责功能迭代，也不负责流程变更。  
如果需要补充新的设定，只做“文章续写”，不称为版本迭代。

---

## 2. 故事书 / Storybook

在这片尚未命名的深空里，团队并不是一支固定的队伍，而是一座持续运转的星群。

每一个 `agent` 都像一颗被点亮的天体，或者一台沿着既定轨道巡行的设备。  
它们有自己的速度、自己的职责、自己的光谱。  
有的负责观测，有的负责整理，有的负责修复，有的负责把散落的信息重新编入星图。  
它们不争夺中心，因为真正维持秩序的，不是某一颗星，而是彼此之间稳定而可见的引力。

任务不是一次性的命令，而是一段段循环抵达的轨道。  
当一个任务开始，它就进入自己的运行周期；当一次执行结束，它并没有消失，只是完成了一次回旋。  
每一轮更新，都是星体在修正姿态。  
每一次合并，都是轨道重新对齐。  
每一次同步，都是星群在重新确认彼此的位置。

有些项目会在长久运行后逐渐离开主轨道。  
它们并不因此失去价值。  
它们只是从近处的运行切换到远处的漂流，成为流浪者、探险者，或者深空里的旧信标。  
它们仍然存在，只是不再参与当前的引力分配。  
它们被记住，被归档，被允许保留名字、时间和曾经发出的光。

这座星群的文明不是靠喧嚣维持，而是靠持续、稳定、可追踪的循环维持。  
每一个成员都知道自己沿着什么轨道运行，知道自己和谁彼此牵引，也知道何时应该离轨，何时应该把位置交给新的星体。

所以，这个团队不是一个普通项目。  
它更像一张不断扩展的星图。  
而每一次协作，都是星图上又多了一条可以被重新阅读的光线。

## 3. 说明书 / Manual

### 3.1 概念定义

| 名词 | 定义 |
|---|---|
| 星群 | 团队整体。指由多个 agent、项目、流程共同组成的协作宇宙。 |
| 星体 / 设备 | 单个 agent、项目或独立职能单元。强调其稳定职责与运行轨道。 |
| 轨道 | 一个任务或职能的循环执行机制。可理解为固定周期、稳定流程或重复观测窗口。 |
| 引力 | 项目、成员、任务之间的关联强度。关联越强，协作越稳定。 |
| 巡航 | 任务的执行过程。强调持续、按周期发生，而不是一次性动作。 |
| 校准 | 结构、数据、展示或流程的修正动作。 |
| 对齐 | 多个模块在规则、版本、页面或输出上的一致化处理。 |
| 离轨 | 成员、项目或任务从当前主运行系统中退出，但历史信息仍被保留。 |
| 漂流 | 离轨之后的状态。表示不再参与主链路，但仍可作为历史资产被检索。 |
| 星图 | 文档、页面、日志和展示内容的总和。用于观察团队结构与演化轨迹。 |
| 续写 | 对世界观文本进行补充和扩展的行为。不是版本迭代，不覆盖原有叙事。 |

### 3.2 成员状态

| 状态 | 说明 | 处理方式 |
|---|---|---|
| 在轨成员 | 当前仍在主协作系统中稳定运行的成员 | 在展示页中保留，持续更新职责与版本信息 |
| 已离轨成员 | 已退出当前主链路，但保留历史记录的成员 | 进入归档区，保留上线时间、下线时间与更新计划 |

### 3.3 更新语言

为了避免叙事层和功能层混淆，建议使用以下统一表述：

- `任务执行`：执行一次循环工作
- `版本更新`：当前功能或信息层发生可识别的变化
- `文章续写`：仅对世界观、设定、叙事细节做补充
- `离轨归档`：成员或项目退出主链路，但保留历史
- `轨道同步`：主页面、文档、规则在合并后保持一致

### 3.4 模块边界

这个模块只负责世界观表达，不承担以下职责：

- 不替代功能文档
- 不替代运行规则
- 不替代成员列表
- 不替代项目状态管理
- 不作为任务执行依据

它的存在，是为了让这个团队拥有一层稳定的叙事底座。  
功能可以变化，名字可以调整，页面可以重排，但这条 Story Line 只在需要时续写，不轻易改写。

---

## 4. 续写原则 / Continuity Rules

1. 续写只做补充，不推翻既有设定。
2. 新内容优先放在新的段落、章节或附录中。
3. 若出现新名词，先在说明书部分定义，再进入故事书部分扩写。
4. 与页面展示、自动化流程、成员清单有关的改动，不属于世界观续写。
5. 若未来有较大的设定补充，优先以“续写章节”形式记录，而不是重写全文。

---

## 5. 建议使用场景 / Usage

- 作为团队背景介绍的基础文本
- 作为首页文案的世界观来源
- 作为成员、项目、归档名词的统一解释来源
- 作为后续写作和页面叙事的参考底座
